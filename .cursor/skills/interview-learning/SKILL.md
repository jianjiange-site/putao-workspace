# 面试学习助手

## 核心定位

这是一个**面试导向的项目学习 Skill**。用户把这个项目当做实习经历，学习后要能在面试中清晰讲解。

## 学习目标

### 方向一：后端/架构常考问题
- 幂等性设计与实现
- 缓存一致性（Cache Aside、写合并、双写问题）
- 分布式锁的实现与踩坑
- 消息队列的使用场景与问题处理
- 数据库事务与并发控制
- 系统设计思路（Feed 流、计数系统）

### 方向二：业务代码实现细节
- 核心功能的落地考量
- 技术选型的权衡过程
- 异常场景的处理策略
- 性能优化的具体手段

## 学习流程

### Step 1: 理解学习上下文

每次学习前，用户会提供：
- **技术文档**：相关设计文档（如 `doc/specs/post-service-design.md`）
- **代码目录**：要学习的模块（如 `post-service/src/main/java/com/dating/post/service/`）

先阅读这些材料，理解：
1. 这个模块要解决什么问题？
2. 采用了什么技术方案？
3. 核心设计点是什么？

### Step 2: 识别面试知识点

从代码中提炼**学习用的知识点**：

```
┌─────────────────────────────────────────────────────────┐
│ 知识点 = 场景 + 问题 + 解决方案 + 权衡 + 实现细节        │
├─────────────────────────────────────────────────────────┤
│ 示例：                                                   │
│ 场景：爆款帖高并发点赞                                   │
│ 问题：直接UPDATE导致单行锁打满PG                         │
│ 方案：Redis写合并 + 批量刷盘                             │
│ 权衡：接受1分钟延迟，换取高性能                         │
│ 实现：Redis INCR + 待刷盘Set + Lua原子操作              │
└─────────────────────────────────────────────────────────┘
```

### Step 3: 创建学习目录结构

在 `doc/course/` 下创建本次学习目录：

```
doc/course/<YYYY-MM-DD>-<模块名>/
├── README.md           # 本次学习的索引/概览
├── prd.md             # 业务功能梳理（类PRD，详细功能流程）
├── knowledge.md        # 核心知识点整理（学习用）
└── interview-qa.md     # 面试问答（面试用）
```

### Step 4: 生成业务功能文档 (prd.md)

重点梳理**业务流程、数据流转、接口设计**，包含所有功能点。PRD 文档要详细，类似产品需求文档：

```markdown
# <模块名> 功能设计文档（类PRD）

## 模块概述
- 业务定位：模块在系统中的位置
- 核心价值：解决什么问题
- 用户角色：谁会使用这个模块

## 功能清单
所有接口/功能的完整列表，以表格形式呈现

| 功能编号 | 功能名称 | 功能描述 | 优先级 |
|---------|---------|---------|--------|
| F001 | 发帖 | 用户发布动态 | P0 |
| F002 | 点赞 | 对帖子点赞/取消点赞 | P0 |
| ... | ... | ... | ... |

## 功能详情

### 功能点 1：XXX

#### 1. 功能描述
[这个功能做什么]

#### 2. 业务规则
- 规则1：什么条件下能做什么
- 规则2：什么条件下不能做

#### 3. 用户交互流程
```
[流程步骤，用序号标注]
例：
1. 用户打开帖子详情页
2. 点击点赞按钮
3. 显示点赞状态
4. 更新点赞数
```

#### 4. 数据流转
```
[数据从哪来、流经哪些系统、到哪去]
例：
用户点击 → HTTP请求 → Gateway → gRPC → PostService
                                          ↓
                                    Redis INCR
                                          ↓
                                    updated_set
```

#### 5. 接口设计

**RPC 接口**：`ActionLike`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| post_id | int64 | 是 | 帖子ID |
| action | int32 | 是 | 1=点赞，0=取消 |

**返回**：
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "success": true
  }
}
```

#### 6. 边界情况
- 用户重复点击：幂等处理，返回成功
- 帖子已删除：返回错误码
- Redis 不可用：降级方案

#### 7. 监控埋点
- `post.like.action`：点赞行为计数
- `post.like.latency`：点赞接口耗时
```

### Step 5: 生成知识点文档 (knowledge.md)

重点整理**纯技术知识**，不涉及面试场景：

```markdown
# <模块名> 知识点整理

## 知识点一：<主题>

### 背景/场景
[在什么业务场景下遇到这个问题]

### 问题分析
[详细分析问题的本质]

### 解决方案
[具体方案]

### 实现细节
[关键代码片段 + 注释]

### 权衡取舍
[为什么选A不选B，trade-off是什么]
```

### Step 6: 生成面试问答文档 (interview-qa.md)

整理**可直接在面试中使用的问答**：

```markdown
# <模块名> 面试问答

## 高频问题

### Q: <问题描述>
**考察点**：<面试官想考察什么>

**标准答案**：
[用STAR法则组织：Situation-Task-Action-Result]
- 场景：我负责...
- 问题：遇到...
- 行动：我采用了...
- 结果：最终...

**追问**：
- Q: 为什么不用XX方案？
  A: [具体解释]

- Q: 极端情况怎么办？
  A: [异常处理]

## 场景问题

### Q: 设计一个XXX系统
**考察点**：系统设计能力

**回答框架**：
1. 需求澄清
2. 数据模型设计
3. 核心接口设计
4. 技术选型
5. 权衡取舍
```

## 文档输出规范

### 目录命名
```

```

### README.md 内容
```markdown
# <模块名> 学习笔记

> 学习日期：YYYY-MM-DD
> 学习范围：<具体模块和功能>

## 本次学习内容

- [业务功能设计](./prd.md) - 功能流程、数据流转、接口设计
- [核心知识点](./knowledge.md) - 技术原理、权衡取舍

## 学习目标

- [ ] 理解XX业务全貌
- [ ] 掌握XX功能的实现细节
- [ ] 能讲清楚XX的技术选型
```

### prd.md 内容（业务功能文档）
- 模块概述
- 功能清单（所有接口一览）
- 功能详情（每个功能：流程、数据流转、接口、边界）
- 数据模型
- 状态机/流转
- 监控指标

### knowledge.md 内容（知识点文档）
- 技术原理
- 实现细节（关键代码）
- 权衡取舍
- 关联知识

### interview-qa.md 内容（面试问答）
- 高频问题及标准答案
- 追问及答案
- 项目讲解话术
- 常见坑及回答

## 注意事项

1. **知识点和问答分开**：知识点是纯学习，问答是面试用
2. **代码即证据**：每个结论都要有具体代码支撑
3. **追问准备**：每个核心问题准备2-3个追问答案
4. **场景还原**：把自己当成真的在这个项目实习过
