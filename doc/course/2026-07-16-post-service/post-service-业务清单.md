# Post Service 业务清单

> 本文只描述用户能使用的功能、业务规则、交互过程和数据流转。RPC、请求/返回结构、错误码和代码实现统一放在 `post-service-业务流程详解.md`。

## 一、模块定位与边界

Post Service 是 Dating App 的内容模块，负责帖子从创建、展示、互动、分发到删除的生命周期：

- 用户发布文本和图片动态；
- 用户查看帖子详情和个人主页帖子；
- 用户点赞、取消点赞、评论、回复和删除评论；
- 系统把热门内容、好友内容和新内容组成推荐 Feed；
- 系统异步维护点赞展示计数、热门池和好友 timeline。

服务只保存图片对象的 key，不负责图片文件上传和存储。用户资料和好友关系属于 user-service；Post Service 只能通过正式的跨服务能力读取，不能直接查询对方数据库。

## 二、用户角色

| 角色 | 主要行为 |
| --- | --- |
| 内容创作者 | 发布动态、查看自己的内容、删除自己的帖子 |
| 内容消费者 | 浏览 Feed、查看详情和用户主页、点赞、评论 |
| 评论作者 | 发布一级评论或回复、删除自己的评论 |
| 后台系统 | 计算热门池、合并点赞计数、异步扩散好友动态、清理历史事件 |

## 四、帖子生命周期

### F001 发布帖子

#### 功能描述

用户发布一条包含正文和可选图片的动态。成功发布后，内容立即具备详情查询能力，并获得冷启动曝光资格；好友扩散由后台异步完成。

#### 业务规则

- 正文必填，最长 1024 个字符。
- 最多携带 9 个图片 key。
- 图片必须在发帖前由客户端完成上传；本服务不处理文件内容。
- 帖子、图片引用、初始统计和待扩散事件必须同时成功或同时失败。
- 数据库成功提交后才写详情缓存和冷启动池。
- 新帖根据作者性别进入对应冷启动池。

#### 用户交互流程

```text
编辑正文并选择图片
  → 客户端完成图片上传
  → 提交正文与图片 key
  → 系统保存帖子
  → 页面显示发布成功
  → 后台继续完成好友扩散和推荐池维护
```

#### 数据流转

```text
正文、图片 key
  → 帖子主记录、图片引用、初始计数、扩散事件
  → 公共详情缓存
  → 冷启动池
  → 后台消息投递
  → 好友 timeline
```

#### 补充说明

好友列表能力目前未由 user-service 正式提供，因此“可靠记录扩散任务”和“发送扩散消息”已经完成，但好友 timeline 暂时取不到真实接收者。热门和冷启动推荐不受此限制。

### F002 查看帖子详情

#### 功能描述

用户查看单条帖子的正文、图片、作者、互动计数，以及自己是否已经点赞。

#### 业务规则

- 已删除帖子不可见。
- 正常状态的帖子对调用者可见。
- 非正常状态的帖子只允许作者本人查看。
- 公共内容可共享缓存；当前用户是否点赞必须按用户单独判断。
- 点赞展示数由数据库基准值和尚未合并的实时增量共同组成。
- 评论数直接使用数据库中的当前值。

#### 用户交互流程

```text
点击帖子
  → 系统读取公共详情
  → 补充实时点赞数、评论数和个人点赞状态
  → 校验帖子可见性
  → 展示完整详情
```

#### 数据流转

公共详情优先从本地缓存和共享缓存读取，未命中时回到数据库；动态计数和用户状态单独读取后再组装。不存在的帖子会被短暂记录，避免相同无效请求持续进入数据库。

### F003 查看用户帖子列表

#### 功能描述

用户进入个人主页，按时间倒序浏览目标用户发布的正常帖子。

#### 业务规则

- 只展示未删除且状态正常的帖子。
- 使用帖子 ID 作为稳定游标，不使用页码跳转。
- 每页最多 50 条。
- 页面中的图片、统计和当前用户点赞状态需要批量组装。

#### 用户交互流程

```text
进入个人主页
  → 加载最新一页
  → 滚动到底部
  → 使用上一页最后一个帖子继续加载
  → 直到没有更多内容
```

#### 数据流转

系统先查询一页帖子主记录，再按整页帖子 ID 批量读取图片、数据库统计、实时点赞增量和当前用户点赞关系，最后保持原帖子顺序组装。

### F004 删除帖子

#### 功能描述

帖子作者删除自己发布的内容。

#### 业务规则

- 只有作者本人可以删除。
- 帖子采用逻辑删除，图片引用会被物理移除。
- 点赞、评论、统计和 timeline 引用暂时保留。
- 数据库提交成功后才清理详情缓存和冷启动池。
- timeline 中残留的帖子 ID 在后续批量读取时会被过滤。

#### 用户交互流程

```text
作者选择删除
  → 客户端二次确认
  → 系统校验作者身份
  → 标记帖子删除并移除图片引用
  → 清理缓存和冷启动曝光
  → 页面移除该帖子
```

## 五、互动

### F005 点赞与取消点赞

#### 功能描述

用户可以点赞或取消点赞。重复提交相同目标状态不会重复改变计数。

#### 业务规则

- 操作前必须确认帖子存在。
- 同一用户和帖子只有一条点赞关系。
- 点赞关系是事实记录；展示计数允许短暂最终一致。
- 只有点赞状态真实变化时，展示计数才增加或减少。
- 展示计数不得小于 0。

#### 用户交互流程

```text
点击点赞按钮
  → 客户端即时切换展示状态
  → 系统原子改变点赞关系
  → 真实变化时更新实时增量
  → 后台定期合并到数据库计数
```

#### 数据流转

点赞关系立即写入数据库；未合并的计数变化写入 Redis 并标记为待处理。读取时将数据库基准与 Redis 增量相加，后台每分钟逐批合并。

#### 一致性说明

点赞关系可用于对账，展示计数不是余额或库存。极端进程崩溃仍可能造成少量计数偏差，生产环境应周期性按照点赞关系重算。

### F006 创建评论或回复

#### 功能描述

用户可以直接评论帖子，也可以回复一级评论或评论线程中的其他回复。

#### 业务规则

- 评论内容必填，最长 512 个字符。
- 发表评论前必须确认帖子存在。
- 回复时，根评论和父评论都必须存在并属于当前帖子。
- 父评论必须属于指定的根评论线程，禁止跨帖子或跨线程回复。
- 系统根据父评论作者计算被回复用户。
- 评论记录和评论数在同一个数据库事务中更新。
- 只有一级评论进入最近评论缓存窗口，回复不占用一级评论位置。

#### 用户交互流程

```text
输入评论或选择回复对象
  → 提交内容
  → 系统校验帖子和评论线程
  → 保存评论并增加评论数
  → 一级评论加入最近评论窗口
  → 页面展示发送结果
```

#### 数据流转

评论及线程关系写入评论表，帖子统计中的评论数同步增加。事务成功后，一级评论 ID 加入最近 200 条评论窗口。

### F007 查看一级评论

#### 功能描述

用户按时间倒序分页浏览帖子的一级评论。楼中楼回复不混入该列表。

#### 业务规则

- 每页最多 50 条。
- 优先读取最近 200 条一级评论窗口。
- 窗口不存在或不能满足本页时回到数据库。
- 多取一条判断是否还有下一页，下一页游标取实际返回的最后一条。
- Redis 路径和数据库路径必须保持相同的一级评论口径。

#### 用户交互流程

```text
打开评论区
  → 加载最新一级评论
  → 滚动加载更多
  → 热数据从评论窗口读取
  → 冷数据或较老评论从数据库读取
```

### F008 删除评论

#### 功能描述

评论作者删除自己发表的评论。

#### 业务规则

- 只能删除自己的评论。
- 使用业务评论 ID 定位评论，不能误用内部自增主键。
- 评论采用逻辑删除。
- 评论记录删除状态和评论数减少必须在同一事务中完成。
- 评论数最低为 0。
- 事务提交后，从一级评论窗口移除对应 ID。

#### 补充说明

当前流程只处理目标评论自身。删除一级评论后，其回复记录的展示和级联策略需要由产品进一步明确，现有实现没有进行整棵评论树的级联删除。

## 六、内容分发

### F009 推荐 Feed

#### 功能描述

用户打开首页时，系统混合返回热门内容、好友动态和处于冷启动期的新帖。

#### 业务规则

- 根据当前用户性别选择目标性别内容池。
- 每 10 个位置以 8 个热门、1 个好友、1 个冷启动为目标。
- 第 3 位优先好友，第 6 位优先冷启动，其余优先热门。
- 指定来源没有候选时允许其他来源补位。
- 已读帖子通过 Bloom Filter 尽量去重。
- 候选失效、已删除或已读时仍推进来源游标，避免下一页重复扫描。
- 候选确定后统一批量读取详情和互动状态。

#### 用户交互流程

```text
打开首页
  → 系统读取三路候选
  → 按固定位置选择并补位
  → 过滤已读和失效帖子
  → 批量组装完整内容
  → 返回本页与下一页游标
```

#### 数据流转

```text
近三天帖子与互动数据 → 热门池
新发布帖子 → 冷启动池
好友扩散消息 → 用户 timeline
三路候选 + 已读 Bloom → 混排候选
候选 ID → 批量帖子详情 → Feed
```

#### 当前限制

好友 timeline 的数据生产依赖正式好友列表。目前该跨服务能力缺失，因此好友来源可能为空，系统会使用热门或冷启动内容补位。

## 七、全局业务边界

| 边界 | 当前处理 |
| --- | --- |
| 图片上传 | 不属于 Post Service，只保存对象 key |
| 帖子编辑 | 当前没有编辑能力 |
| 审核流程 | 存在状态和可见性判断，但没有完整审核工作流 |
| 评论树删除 | 没有级联删除整棵回复树 |
| 好友列表 | user-service 尚无正式接口，好友扩散无法完成真实 fanout |
| 点赞计数绝对准确 | 允许最终一致，需对账兜底 |
| 缓存失效零陈旧 | Redis Pub/Sub 可能漏收，本地 15 秒 TTL 兜底 |
